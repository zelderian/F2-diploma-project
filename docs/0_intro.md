# ВСТУП

## Актуальність теми

Розвиток кооперативних багатокористувацьких ігор супроводжується зростанням вимог до коректності та стабільності мережевої взаємодії. Ключовими інженерними проблемами є синхронізація стану між клієнтами за умов мережевої затримки (Latency) та втрати пакетів, захист ігрової логіки від маніпуляцій з боку клієнтської сторони (Cheating), а також відтворюваність збірок і контроль якості C++ коду великої кодової бази. Модель Listen Server, де роль хоста виконує один із гравців, не забезпечує авторитетності стану гри та відмовостійкості сесії.

Вирішення зазначених проблем потребує переходу до архітектури з виділеним авторитетним сервером (Authoritative Dedicated Server), контейнеризації серверного компонента, автоматизації збірки, тестування та аналізу якості коду (CI/CD, SonarQube, Trivy), а також впровадження спостережуваності (Observability) на основі метрик Prometheus та Grafana. Поєднання цих підходів у межах єдиного інженерного рішення визначає актуальність теми.

## Об'єкт дослідження

Процес мережевої синхронізації та обробки ігрових подій у кооперативних багатокористувацьких сесіях за умов змінної мережевої затримки.

## Предмет дослідження

Методи та архітектурні патерни забезпечення авторитетності й відмовостійкості ігрового сервера (Authoritative Server, реплікація стану, серверна валідація RPC), а також технології контейнеризації, автоматизації CI/CD та спостережуваності (Unreal Engine 5, Docker, GitHub Actions, SonarQube, Trivy, Prometheus, Grafana).

## Мета роботи

Проєктування та розробка кооперативної багатокористувацької гри на Unreal Engine 5 з архітектурою Authoritative Dedicated Server, контейнеризацією та автоматизованим CI/CD-конвеєром з метою підвищення коректності синхронізації стану, захищеності від маніпуляцій клієнта та відтворюваності процесу збірки і розгортання.

## Завдання проєкту

1. Проаналізувати існуючі аналоги кооперативних багатокористувацьких ігор та мережевих платформ, визначити їхні архітектурні обмеження.
2. Обґрунтувати вибір технологічного стеку та архітектурних патернів проєкту.
3. Спроєктувати архітектуру системи за допомогою UML та моделі C4 із фіксацією рішень у документах ADR.
4. Розробити алгоритми критичних вузлів: серверну валідацію дій гравця, реплікацію стану, розподільник появи ворогів (Spawn Director) та ідемпотентне збереження результатів матчу.
5. Спроєктувати схему розгортання та реалізувати контейнеризований Dedicated Server із розгортанням у хмарі (AWS EC2).
6. Виконати інструментальний аудит якості коду та безпеки засобами Unreal Automation Tests, SonarQube, Trivy та навантажувального тестування.
7. Апробувати результати роботи та підготувати науковий виклад (статтю) за результатами дослідження.
