## Робоча назва

**Українською:** Проєктування та розробка кооперативної багатокористувацької гри на Unreal Engine 5 з архітектурою Authoritative Dedicated Server, контейнеризацією та автоматизованим CI/CD-конвеєром.

**Англійською:** Design and Development of a Cooperative Multiplayer Game on Unreal Engine 5 with Authoritative Dedicated Server Architecture, Containerization and Automated CI/CD Pipeline.

## Актуальність та проблематика

Розробка багатокористувацьких ігор пов'язана з низкою інженерних проблем: синхронізація стану між клієнтами за умов мережевої затримки (Latency) і втрати пакетів, захист від маніпуляцій з боку клієнта (Cheating), масштабованість ігрових сесій, відтворюваність збірок та контроль якості C++ коду великої кодової бази. Модель Listen Server, у якій хостом є один із гравців, не забезпечує ні авторитетності стану гри, ні стабільності сесії. Тому актуальною є побудова архітектури з виділеним авторитетним сервером, який ізолює ігрову логіку від клієнта, у поєднанні з автоматизацією збірки, тестування та моніторингу.

## Ідея продукту

Розподілена клієнт-серверна система, що складається з клієнта на Unreal Engine 5, контейнеризованого Dedicated Server, допоміжного сервісу прогресії гравців (REST API та PostgreSQL) і контуру CI/CD та спостережуваності (Observability). Прикладною областю є кооперативна гра жанру PvE-шутер на виживання для 2-3 гравців.

Ядром проєкту є функції 1, 2 та 7; функції 3 і 5 реалізуються у мінімальному обсязі.

## Ключові функції

1. Авторитетний виділений сервер (Authoritative Dedicated Server): серверна перевірка руху, стрільби та шкоди, реплікація стану (Replication, RPC) для 2-3 клієнтів зі стабільним Tick Rate не нижче 30 Гц та піковою затримкою (Latency) не більше 100 мс.
2. Керування сесіями: створення лобі, приєднання до сесії, підбір гравців на базі Epic Online Services (Online Subsystem).
3. Хвильова PvE-система: штучний інтелект ворогів (Behavior Trees, EQS) та серверний розподільник появи ворогів (Spawn Director) із динамічною складністю.
4. Серверний захист від маніпуляцій: валідація RPC, обмеження частоти запитів (Rate Limiting), перевірка допустимості дій гравця.
5. Сервіс збереження прогресії: REST API для профілів, статистики та інвентарю гравців зі зберіганням у PostgreSQL з ідемпотентним збереженням результатів матчу, що виключає дублювання записів при повторній відправці.
6. Телеметрія та спостережуваність: експорт метрик сервера (Tick Rate, Ping, кількість гравців, використання пам'яті) у Prometheus з візуалізацією в Grafana.
7. Автоматизований CI/CD: збірка Dedicated Server у Docker-образ, запуск Unreal Automation Tests, статичний аналіз коду (SonarQube), сканування образів (Trivy), навантажувальна симуляція ботами та перевірки працездатності (Health Checks) з автоматичним перезапуском контейнера Dedicated Server.
